## 1. 项目速览

**一句话定位**：面向 6~12 岁儿童的家庭作业激励应用——任务打卡获得积分，连击/徽章强化习惯，积分兑换奖品（家长审核），家长端统一管控多孩子数据。

| 维度 | 内容 |
|------|------|
| 形态 | 移动端优先 SPA（React 19 + Vite 7 + TypeScript strict） |
| 后端 | Supabase：Auth（邮箱/用户名）+ Postgres + RLS + Realtime |
| 数据模式 | 本地 localStorage 兜底 + 云端独立表同步（`useSyncedAppState` 编排） |
| UI | shadcn/ui + Tailwind 3 + 设计 Token（`docs/design-system.md` v2.0 亮色乐园） |
| 质量门禁 | `tsc -b` → `pnpm build` → `pnpm test`（Vitest，CI 强制）；lint 暂不阻塞 |
| 最新版本 | v2.1.2（详见 CHANGELOG） |

## 3. 数据库全景

后端为 Supabase Postgres。Schema 资产分两套并存：

- **`supabase/migrations/`** —— 标准迁移基线（若走 Supabase CLI `db push`）：`20260814120000_initial_schema.sql`（11 业务表 + `data_backups` + RLS + 安全函数，幂等）、`20260814120001_add_updated_at_triggers.sql`
- **`sql/`** —— Dashboard SQL Editor 手工执行的脚本（README 现行方式），含基线与全部增量

### 3.1 表清单（12 张）

| 表 | 用途 | 核心字段 | 来源脚本 |
|----|------|----------|----------|
| `profiles` | 用户档案（一表双角色） | `role`(parent/child)、`parent_id`、`total_points`、`username`、`phone` | 基线 |
| `tasks` | 作业库任务 | `name`、`base_points`、`icon`、`is_active`、`is_temporary`、三级分类外键 | 基线 + Next |
| `daily_records` | 每日完成记录 | `date`、`tasks`(jsonb 快照)、`total_points`，`UNIQUE(user_id,date)` | 基线 |
| `rewards` | 奖品库 | `name`、`points`、`icon`、`category`(4 枚举) | 基线 |
| `redemptions` | 兑换记录 | `reward_id`(可空·SET NULL)、`reward_name`/`points` 快照、`status`(pending/approved/fulfilled/rejected) | 基线 + Now |
| `badges` | 已解锁徽章 | `badge_type`，`UNIQUE(user_id,badge_type)` | 基线 |
| `custom_badges` | 家长自定义徽章定义 | `name`、`icon`、解锁条件 | Later |
| `point_adjustments` | 手动加减分流水 | `points`(±)、`reason`(必填) | 基线 |
| `primary_categories` | 一级分类（学习/运动…） | `name`、`icon`、`key` | 基线 |
| `secondary_categories` | 二级分类 | `primary_category_id`、`name` | 基线 |
| `tertiary_categories` | 三级分类（任务级） | `default_points`、`repeat_rule`(jsonb 重复规则)、`secondary_category_id` | 基线 + Next |
| `data_backups` | 云端备份快照（重置/操作前） | `backup_data`(jsonb) | 仅 migrations 基线 |

> ⚠️ 差异提醒：`sql/full-schema.sql` 是早期整合基线，**不含** `data_backups`、`custom_badges`、`redemptions.status`、`tasks.is_temporary`、`repeat_rule`——新库跑完它仍需按 §3.4 顺序补齐增量脚本。

### 3.2 函数 / RPC

| 对象 | 用途 | 来源 |
|------|------|------|
| `is_parent(uid)` | RLS 判「当前用户是家长」（SECURITY DEFINER，防递归） | Now |
| `get_email_by_username(text)` | 用户名→邮箱反查（用户名登录，精确匹配防枚举） | `username-login.sql` |
| `create_child_account(username,password,parent_id)` | 家长代建子账号，一次完成 auth.users+profiles（绕过 signUp 邮件/限流） | `create-child-account.sql` |
| `initialize_default_categories_for_user` / `handle_new_user` | 注册自动建 profile + 默认三级分类 | 基线 |
| `calculate_user_total_points` / `update_user_total_points` / `handle_point_adjustment` / `handle_redemption` / `handle_daily_record_change` | DB 侧积分联动兜底 + 对应触发器 | 基线 |
| `update_updated_at_column` | 统一维护 `updated_at` | 基线 + migrations |

### 3.3 视图 / 触发器 / 索引

- **视图**：`user_category_hierarchy`（三级分类层次查询）
- **触发器**：`on_auth_user_created`（注册初始化）、8 张表 `update_*_updated_at`、3 个积分联动触发器（`on_point_adjustment_created` / `on_redemption_created` / `on_daily_record_changed`）
- **索引**：全部业务表 `user_id` 索引 + 外键/日期/状态列索引（见 full-schema 尾部）

### 3.4 SQL 脚本执行矩阵

**场景 A · 全新环境**（按序执行，均为幂等脚本可重复跑）：

```
① supabase/migrations/…initial_schema.sql   （或 sql/full-schema.sql）
② sql/now-phase-trust-fix.sql               P0：redemptions.status + is_parent() + 家长 RLS
③ sql/next-phase-growth-retention.sql       P1：is_temporary / repeat_rule / 多孩子 RLS
④ sql/later-phase-scale-compliance.sql      Later：custom_badges
⑤ sql/username-login.sql + create-child-account.sql   功能 RPC
```

**场景 B · 存量库升级**：

| 症状 | 处置 |
|------|------|
| 兑换报 `Could not find the 'status' column of 'redemptions'`（schema cache） | 先跑 `fix-redemption-status-only.sql` 急救（仅补 status + NOTIFY 刷新缓存），再抽空跑 ② 拿全量 RLS 审核能力 |
| 兑换正常但家长无法审核 | 跑 ②（`is_parent()` + redemptions 家长策略） |
| 想用临时任务/重复规则/多孩子 | 跑 ③ |
| 想用自定义徽章 | 跑 ④ |

**运维查询**：`sql/query-child-accounts.sql`（列 @example.com 子账号与最近登录）。

## 4. 核心业务规则速查

| 规则 | 说明 |
|------|------|
| **兑换状态机** | 孩子发起 → `pending`（积分冻结不扣）→ 家长通过 `approved` → 兑现 `fulfilled`（正式扣分）/ 驳回 `rejected`（退还） |
| **可用积分** | `可用 = 总积分 − 冻结积分（pending 兑换之和）`，奖品墙与兑换均以此为准 |
| **总积分口径** | 完成任务加分 + 家长手动调整 ± − 已审核兑换（approved/fulfilled）；以**前端计算为准**（DB 触发器为历史兜底） |
| **连击 Streak** | 每日完成率 ≥ 阈值(默认 80%)记达成日；漏签可用 20 积分买**补签卡**补昨天 |
| **临时任务** | 今日清单临时添加，不入作业库，`is_temporary=true` |
| **角色权限** | 家长：配任务/建子账号/调分/审核兑换/备份重置/徽章管理；孩子：打卡/看积分徽章/发起兑换（规则操作隐藏） |
| **ID 约定** | 前端 `crypto.randomUUID()` 生成后显式携带 insert，本地与云端主键必须一致（v2.1.1 已根治） |
| **数据备份** | 设置页导出 JSON + 云端 `data_backups` 快照；重置前强制自动备份 |
