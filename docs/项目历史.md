#### 核心功能点

| # | 变更          | 说明                                                                                                                                                                                                                      |
| - | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | 修复时区日期 Bug  | 新增 `src/utils/date.ts`（`getTodayStr` / `getYesterdayStr` / `daysBetween`，统一本地时区）；全项目替换 17 处 `new Date().toISOString().split('T')[0]`（原基于 UTC，北京时间凌晨 0–8 点会记成前一天，影响今日任务、连续天数、积分统计）；`calculateStreak` 同时修正 `86400000` 硬编码 |

| 4 | 清理生产日志      | 全项目删除 93 处 `console.log`（useSyncedAppState 67 处、useSupabaseData 15 处、视图层 11 处），消除用户 ID / 数据明细在生产环境的打印泄漏；保留 `console.error` 错误处理                                                                                         |

### 2026-08-14｜阶段二：架构重构（中风险，单独排期）

**背景**：依据《项目结构梳理与优化建议》阶段二计划执行。目标：状态层职责拆分、消除 prop drilling、类型安全收口、SQL 工程化。对外功能定义不变。

#### 核心功能点

| # | 变更               | 说明                                                                                                                                                                                                                                            |
| - | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | SQL 迁移工程化        | 新增 `supabase/migrations/`：`20260814120000_initial_schema.sql`（11 张表基线 + RLS + 幂等策略，补上了此前仅在控制台手建的 `data_backups` 表）、`20260814120001_add_updated_at_triggers.sql`（统一 `set_updated_at` 触发器，覆盖 8 张表）                                              |
| 2 | 类型安全收口           | `lib/supabase.ts` 客户端接入手写 `Database` 泛型（修复：`interface`→`type alias`、补 `Views/Functions/Relationships` 键、`profiles.phone` 字段）；全项目 `any` 清零（28→0），eslint 开启 `@typescript-eslint/no-explicit-any: error` 门禁；删除 6 处 `@ts-ignore`（未用 props/函数直接移除） |
| 3 | 状态层拆分            | 新增 `src/services/supabaseApi.ts`（507 行，类型化数据访问层：行↔模型映射、10 表并行拉取、全部写入操作、Realtime 订阅）；`useSyncedAppState.ts` 由 1,662 行瘦身至约 1,000 行，职责收敛为「状态管理 + 加载编排 + 持久化/备份 + 副作用」，对外 API 不变                                                                  |
| 4 | 消除 prop drilling | 新增 `src/contexts/AppStateContext.tsx`（`AppStateProvider` / `useAppState`）；7 个视图（Home/Tasks/Rewards/Achievements/Settings/Profile/PointManagement）改为 Context 消费状态与业务操作，`App.tsx` 由 307 行精简至约 210 行，仅保留导航；toast 反馈逻辑内聚到各视图                      |
| 5 | totalPoints 一致性  | 积分重算统一收敛在 store 层（`calculateTotalPoints` 兜底校准保留），避免各方法散落重复；`totalPoints` 字段保留存储以兼容 localStorage 旧数据与 profiles 同步，完全派生化列入后续                                                                                                                    |
