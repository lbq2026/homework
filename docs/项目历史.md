### 2026-09-04｜修复：兑换记录次日丢失（ID 双轨错位根治）+ 环境重建

**背景**：用户反馈"兑换了奖品、积分已扣，第二天兑换记录消失、积分重置"。同日完成 pnpm store 损坏后的依赖全量重建与 CI 门禁验证。

#### 核心功能点

| # | 变更 | 说明 |
| - | ---- | ---- |
| 1 | 根治 ID 双轨错位 | `insertTask/insertPrimaryCategory/insertSecondaryCategory/insertTertiaryCategory/insertReward/insertRedemption` 全部显式携带前端生成的 id；此前云端另行生成主键，导致本地 id ≠ 云端 id |
| 2 | 兑换链路死亡链修复 | reward 双轨 id → `redemptions.reward_id` 外键违规 → 兑换记录从未入库（console.error 静默）→ 次日 `buildStateFromDb` 用云端空表重建 → 记录消失/积分"复原"。这是用户所见 bug 的直接根因 |
| 3 | 审核同步修复 | `updateRedemptionStatus` 改为返回 affected rows（`.select('id')`），approve/reject/fulfill 匹配 0 行时自动 `refreshData()` 对齐云端，消除"本地已审核、云端仍 pending" |
| 4 | redemptions Realtime 订阅 | `subscribeToChanges` 新增 `onRedemptionsChange`，家长端审核后孩子端即时刷新（此前 6 表订阅独缺此表） |
| 5 | 兑换失败阻断 | `redeemReward` 云端插入失败返回 false，不再盲目写入本地 |
| 6 | refreshData 上移 | 定义移至兑换区块之前，消除 `approveRedemption` 依赖数组引用后置 const 的 TDZ 隐患 |
| 7 | 单测夹具修复 | `storage.test.ts` 的 `makeDailyRecord` 默认传 undefined 触发派生分支（原 totalPoints:0 短路了待测路径），18/18 通过 |
| 8 | 兑换 FK 降级兜底 | `insertRedemption` 首插遇 23503（`reward_id` 指向云端不存在的奖品，即存量双轨/云端奖品缺失）自动降级为 `reward_id=NULL` 重插：记录与积分口径不丢，仅牺牲云端奖品关联（本地 UI 不受影响） |
| 9 | 兑换失败可见性 | `redeemReward` 返回 `{ ok, reason: 'no-user'\|'insufficient'\|'cloud-error', message }`；Rewards 页失败分别 toast（此前静默无反馈，表现为"确认按钮点了没反应"） |

> 补充：修复 5（兑换失败阻断）将"云端写入假数据"改为"硬阻断"后，存量奖品因外键缺失导致的兑换失败从"静默丢数据"变成了"静默无反应"。本条目 #8/#9 为其收尾：外键缺失自动降级（仍成功落库），其余失败全部可见可诊断。

#### 验证

- `tsc -b` ✅ / `vitest` 18/18 ✅ / `pnpm build` ✅（38.9s）
- lint 既有 38 处历史报错与本变更无关（CI 中 lint 不阻塞）

#### 涉及文件

- 修改：`src/services/supabaseApi.ts`（insert 系列 +id 参数、insertRedemption FK 23503 降级兜底、updateRedemptionStatus 返回 count、订阅新增 redemptions）
- 修改：`src/hooks/useSyncedAppState.ts`（6 处调用传本地 id、redeemReward 结构化结果、审核三函数 0 行兜底、refreshData 上移、注册订阅）
- 修改：`src/views/Rewards.tsx`（兑换失败分原因 toast，不再静默）、`src/utils/__tests__/storage.test.ts`、`docs/CHANGELOG.md`（v2.1.1）、`README.md`（文档完善）、`pnpm-lock.yaml`（store 重建）

#### 遗留风险

- 存量脏数据已缓解：修复前错位的旧兑换记录云端仍无法被审核（0 行 → 自动刷新对齐），但新发起兑换已通过 FK 降级兜底保证落库；旧记录仍需用户重新发起
- `database.ts` 中 `redemptions.reward_id` 类型仍为非空 `string`（DB 实际可空），insertRedemption 降级分支用断言绕过；后续若整体重生成 DB 类型应同步对齐
- `syncLocalStateToDb` 上传路径未同步修改（本地→云端初始化场景，upsert 带 id，本身一致）
