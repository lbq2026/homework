## 1. 产品概述与定位

**一句话定位**：面向 6~12 岁儿童的"作业打卡 + 积分激励"家庭管理工具，让写作业从"家长催促"变成"孩子主动"。

**核心价值主张**：

- **对孩子**：把作业变成游戏——完成任务获得积分、解锁徽章、兑换奖品，获得即时正反馈；
- **对家长**：把"催作业、讲道理"变成"定规则、看数据"——配置任务、设定奖品、查看成长轨迹。

**当前产品形态**：移动端优先的 SPA（单账号、单孩子数据模型），Supabase 提供账号体系与云同步，已具备"作业 → 积分 → 兑换"的完整业务闭环雏形。

## 2. 用户画像与核心场景

| 角色 | 年龄 | 核心诉求 | 使用频率 | 关注点 |
|------|------|----------|----------|--------|
| **孩子（小勇士）** | 6~12 岁 | 好玩、有奖励、看得见的成长 | 每日 1~2 次 | 积分增长、徽章解锁、兑换心仪奖品 |
| **家长（管理员）** | 30~45 岁 | 省心、可控、数据可追溯 | 每周 3~5 次 | 任务是否完成、积分是否合理、孩子成长趋势 |

**关键场景**：

1. **日常打卡**（孩子，每日）：打开 App → 查看今日清单 → 逐项完成 → 看积分上涨 → 偶尔兑换奖品；
2. **规则配置**（家长，每周）：维护作业库/分类 → 设定奖品 → 调整积分；
3. **成长回顾**（家长，每月）：查看孩子完成情况、徽章解锁、趋势变化。

## 4. 核心闭环与断裂点分析

### 4.1 核心闭环

```
家长配置规则                孩子执行                   获得反馈
┌─────────────┐    ┌───────────────┐    ┌─────────────────────┐
│ 建分类/任务   │ →  │ 今日清单打卡    │ →  │ 积分↑ / 徽章解锁 /   │
│ 设奖品/积分  │    │ 完成任务       │    │ 兑换奖品            │
└─────────────┘    └───────────────┘    └─────────────────────┘
```

**业务闭环完整度评估：闭环已通，但三个环节存在信任与体验断裂。**

### 4.2 关键断裂点

| # | 断裂点 | 表现 | 后果 |
|---|--------|------|------|
| B1 | **无角色权限边界** | 注册时可选"家长/孩子"，但**任何角色登录后操作权限完全一致**——孩子可以自行加减积分、改奖品、删兑换记录 | 激励体系可被"作弊"，家长失去掌控感，产品可信度归零 |
| B2 | **完成即积分，无验收环节** | 孩子勾选"完成"立即加分，无需家长确认 | 无法约束"糊弄式完成"，积分含金量低 |
| B3 | **兑换即扣分，无兑现闭环** | 点击兑换立即扣积分，兑换记录无"待兑现/已兑现"状态 | 孩子乱点兑换 → 家长被迫手动撤销，体验混乱 |
| B4 | **单孩子模型，无家庭维度** | `profiles.parent_id` 字段已建但未使用，一个账号一套数据 | 二胎家庭无法统一管理；换设备/换账号数据割裂 |
| B5 | **连击规则过于严苛** | 要求"当天**所有**任务全部完成"才算连续 1 天 | 一天漏一项即断签，挫败感强，孩子容易放弃 |

## 5. 问题诊断（按优先级分级）

> 优先级定义：**P0 = 影响产品成立/信任根基**；**P1 = 影响核心体验与留存**；**P2 = 增强型机会**。

### 5.1 P0 —— 产品逻辑漏洞（必须优先解决）

| ID | 问题 | 证据（代码） | 影响 |
|----|------|-------------|------|
| P0-1 | 角色权限未落地，孩子可"自作弊" | `Auth.tsx` 注册可选角色；`PointManagement.tsx` 手动加减分、`Rewards.tsx` 删奖品、`Settings.tsx` 重置全部——**均无 role 校验** | 积分/兑换体系失去信任，家长弃用 |
| P0-2 | 兑换无审核/兑现状态 | `Rewards.tsx` redeem 即扣分，redemption 记录无状态字段 | 孩子误操作无挽回，家长需手动撤销 |
| P0-3 | 数据可被任意重置 | `Settings.tsx` 任何登录用户可"重置所有数据" | 一次误触，全部记录丢失（虽有备份但体验恶劣） |

### 5.2 P1 —— 体验与留存短板

| ID | 问题 | 表现 | 影响 |
|----|------|------|------|
| P1-1 | 家长视角缺失 | 无"家长工作台"，无多孩子管理 | 家庭场景无法成立 |
| P1-2 | 无成长趋势可视化 | 成就页只有静态数字，无积分曲线/完成率趋势 | 家长看不到"成长"，留存动机弱 |
| P1-3 | 任务安排能力弱 | 只有"今日清单"，无周期性任务/周计划 | 家长每天重复配置，负担重 |
| P1-4 | 无任何提醒能力 | 无 PWA 推送/站内提醒（docs/ 已有 PWA 评估但未实施） | 孩子忘记打卡，连击流失 |
| P1-5 | 新用户引导缺失 | 注册后直接进入空状态，无引导流程 | 首用流失风险高 |

### 5.3 P2 —— 增强机会

| ID | 问题 | 说明 |
|----|------|------|
| P2-1 | 临时任务入口缺失 | `Task.isTemporary` 字段已定义但无 UI，无法创建一次性任务 |
| P2-2 | 徽章体系封闭 | 12 种徽章硬编码于 `storage.ts`，无法自定义或扩展 |
| P2-3 | 反馈形式单一 | 完成任务仅 toast + 彩带动画，音效仅完成音 |
| P2-4 | 密码重置链路断裂 | `useAuth.tsx` 跳转 `/reset-password`，但 `App.tsx` 路由表**无此路由** |
| P2-5 | 手机号字段空转 | profile 可编辑手机号，但 Supabase 手机认证未启用，字段无实际用途 |
| P2-6 | 儿童隐私合规未标注 | 儿童数据涉及个保法/COPPA 敏感点，无隐私说明与家长同意机制 |

## 6. 优化建议清单

> 每条建议按统一模板输出：**问题 → 建议方案 → 用户故事 → 预期指标 → 工作量/风险**。
> 工作量为相对估算：S（≤1天）/ M（2~3天）/ L（1~2周）/ XL（>2周）。

### 6.1 核心闭环强化（P0）

#### 建议 1：落地角色权限体系（家长/孩子视图分离）⭐ 优先级最高

- **问题**：P0-1。当前任何角色权限一致。
- **方案**：
  - 基于 `profiles.role` 做前端路由守卫 + 后端 RLS 双保险；
  - **孩子端**（默认落地）：任务打卡、查看积分/徽章、发起兑换——但**不可**手动加减分、不可删除奖品、不可重置数据；
  - **家长端**：作业库配置、奖品管理、积分调整、数据管理、多孩子切换、孩子操作审计。
- **用户故事**：
  - 作为**孩子**，我希望我不能修改积分和奖品，以便我的成绩真实可信；
  - 作为**家长**，我希望所有规则类操作由我完成，以便我掌握激励体系的控制权。
- **预期指标**：家长周登录率 ≥ 60%；积分调整异常率下降（作弊类投诉归零）。
- **工作量/风险**：M。风险：需同步梳理 RLS 策略（已有 `sql/fix-rls-*.sql` 修复基础），避免权限回归。

#### 建议 2：兑换审核与兑现状态机

- **问题**：P0-2。兑换即扣分，无状态。
- **方案**：`redemptions` 增加 `status` 字段（`pending` → `approved` → `fulfilled` / `rejected`）：
  - 孩子兑换 → 积分**冻结**（进入 pending）→ 家长确认 → 扣分兑现或驳回退还；
  - 兑换记录页展示状态徽标，家长可操作审核。
- **用户故事**：
  - 作为**孩子**，我希望兑换后能看到"等待妈妈确认"，以便我知道奖品什么时候能到手；
  - 作为**家长**，我希望审核兑换请求，以便我不被孩子乱点兑换困扰。
- **预期指标**：兑换驳回率 < 20%；兑换完成率（fulfilled/总兑换）≥ 70%。
- **工作量/风险**：M。风险：冻结逻辑需与 `calculateTotalPoints` 联动，注意积分口径统一。

#### 建议 3：数据保护（重置操作二次鉴权）

- **问题**：P0-3。任意用户可重置全部数据。
- **方案**：重置入口仅家长可见；操作要求输入账号密码或二次确认码；重置前强制创建云端备份快照。
- **用户故事**：作为**家长**，我希望误触重置也能找回数据，以便我不必担心孩子乱点。
- **预期指标**：数据丢失类工单归零。
- **工作量/风险**：S~M。

### 6.2 成长与体验增强（P1）

#### 建议 4：多孩子档案管理（家庭空间）

- **问题**：P1-1。单账号单孩子。
- **方案**：
  - 家长账号下可创建/邀请多个孩子档案（复用 `parent_id` 字段）；
  - 顶部提供孩子切换器；每个孩子独立积分、任务、徽章；
  - 家长端可一键查看任一孩子的数据面板。
- **用户故事**：
  - 作为**家长**，我希望一个账号管理两个孩子的作业和积分，以便公平激励每个孩子；
  - 作为**孩子**，我希望打开 App 看到的是"我"的数据，以便我的进步不被混淆。
- **预期指标**：家庭场景（≥2 孩子）使用占比；孩子档案创建数/家长。
- **工作量/风险**：L。风险：数据隔离复杂度提升，RLS 需按 parent_id/child_id 双维度调整。

#### 建议 5：成长报告与趋势可视化

- **问题**：P1-2。
- **方案**：
  - 成就页增加**积分趋势折线**（近 7/30 天）、**分类完成占比**（雷达/环形图）、**周完成率**；
  - 生成**每周成长周报**（自动汇总：完成数、积分、徽章、与上周对比），家长端可查看。
- **用户故事**：
  - 作为**家长**，我希望一眼看到孩子本周的进步曲线，以便判断激励策略是否有效；
  - 作为**孩子**，我希望看到自己的积分在涨，以便获得持续动力。
- **预期指标**：家长月活（查看报告次数）；7 日留存。
- **工作量/风险**：M（趋势图用现有 recharts 依赖，成本低）。

#### 建议 6：任务计划系统（周期性任务）

- **问题**：P1-3。
- **方案**：
  - 任务支持**重复规则**（每天/每周固定日/自定义）；
  - 新增"一键生成今日清单"：按重复规则自动填充今日任务；
  - 支持任务模板（如"阅读 20 分钟"一键套用）。
- **用户故事**：
  - 作为**家长**，我希望"周一三五跳绳"这类任务自动出现在当天清单里，以便我不必每天手动添加。
- **预期指标**：每日清单手动配置时间下降（目标 -50%）。
- **工作量/风险**：L。风险：重复规则与"临时任务"（P2-1）需统一建模。

#### 建议 7：连击规则友好化 + 补签机制

- **问题**：P0/B5。全完成才计连击，过于严苛。
- **方案**：
  - 完成率 ≥ 80% 即视为"当日达成"（或提供两档规则供家长选择）；
  - 增加**补签卡**道具（用积分兑换，可补回一天连击）；
  - 断签时展示安抚文案而非单纯归零。
- **用户故事**：
  - 作为**孩子**，我希望偶尔漏一项作业也能保住连击，以便我不至于因为一次失误就放弃。
- **预期指标**：连击中断后 7 日回归率；3 日以上连击保持人数。
- **工作量/风险**：M。

#### 建议 8：提醒能力（PWA 推送）

- **问题**：P1-4。项目已有 PWA 评估文档，未落地。
- **方案**：接入 Web Push（或降级方案：站内通知 + 每日邮件），支持"作业提醒"、"连续打卡提醒"。
- **用户故事**：作为**孩子**，我希望晚上 7 点收到"今日任务还没完成哦"的提醒，以便我不忘记打卡。
- **预期指标**：提醒触达率 → 完成率提升 ≥ 15%。
- **工作量/风险**：L~XL（依赖 PWA/服务端推送基础设施）。

#### 建议 9：新手引导（First-run 体验）

- **问题**：P1-5。
- **方案**：注册后 3~4 步引导：选择角色 → 创建默认分类 → 添加第一个任务 → 认识积分/兑换。配合现有触发器默认分类，低成本高收益。
- **用户故事**：作为**新家长**，我希望 3 分钟内完成初始化配置，以便尽快开始使用。
- **预期指标**：首日激活率（注册后 24h 内产生首个任务）。
- **工作量/风险**：S~M。

### 6.3 增强机会（P2）

| ID | 建议 | 说明 | 工作量 |
|----|------|------|--------|
| P2-1 | 临时任务入口 | 复用 `isTemporary` 字段，今日清单支持"添加一次性任务"（不进入任务库） | S |

## 7. 指标体系设计

### 7.1 北极星指标

> **北极星：孩子周任务完成率**（本周实际完成任务数 ÷ 本周应完成任务数）

它同时度量了：任务规划质量（家长）、执行意愿（孩子）、激励有效性（产品）。

### 7.2 指标分层

| 层级 | 指标 | 定义 | 数据来源 |
|------|------|------|----------|
| **北极星** | 周任务完成率 | 本周完成数/应完成数 | daily_records |
| **驱动** | 日活孩子数（DAU） | 当日有打卡行为的用户 | 访问日志 |
| | 人均日完成数 | 完成任务数/活跃孩子 | daily_records |
| | 连击保持率 | 连续 ≥3 天的用户占比 | streaks |
| | 兑换转化率 | 兑换次数/浏览奖品次数 | redemptions |
| **健康** | 7 日留存 | 注册后 7 天仍活跃 | 用户表 |
| | 徽章解锁率 | 解锁 ≥3 徽章用户占比 | badges |
| | 家长周登录率 | 家长每周打开次数 | 访问日志 |
| **护栏** | 积分异常调整率 | 非任务来源积分变动占比 | point_adjustments |
| | 兑换驳回率 | 驳回/总兑换 | redemptions |

> 建议上线埋点后按周复盘，北极星指标波动 >±10% 时触发产品例会讨论。
